# PagePilot — версия 2.0

Самописная админка для управления AI-генерацией SEO-контента и публикацией
готовых JSON-данных в существующую систему через endpoint.

## Что внутри

- `frontend` - React/Vite админка без Tailwind и без CDN.
- `backend` - FastAPI API, валидация, задачи генерации и публикации.
- `infra/nginx` - production reverse proxy под доступ по IP.
- `docker-compose.yml` - полный запуск: frontend, backend, postgres, redis,
  celery worker, celery beat, nginx.

## Локальный/серверный запуск

```bash
cp .env.example .env
docker-compose up -d --build
```

После запуска:

- UI: `https://ai-seo-content-panel.site`
- API health: `https://ai-seo-content-panel.site/api/health`

## Редакционный скилл генерации

Перед ТЗ каждого запроса на генерацию контента автоматически добавляется полный
текст [AI-нейтрализатора](backend/app/data/ai_neutralizer.md). Он применяется
к стандартным и пользовательским шаблонам через общий сборщик запроса
`build_gemini_prompt`, включая повторную генерацию. ТЗ определяет параметры
задачи и формат ответа. Сам скилл не подключает инструменты веб-поиска.

При включённом сборе конкурентов перед генерацией статьи Gemini составляет
план проверки недостающих фактов. Сначала отдельный вызов Gemini с инструментом
`url_context` анализирует до 10 исходных URL конкурентов из DataForSEO.
Анализ принимается только для URL с успешным статусом чтения в метаданных
провайдера; статусы и анализ видны в блоке «Поиск фактов». Если модель или
endpoint не поддерживают инструмент, ошибка сохраняется, работа продолжается
с имеющейся сводкой и выдержками. Google Search в Gemini не включается.
URL Context расходует токены Gemini, но не поисковые запросы DataForSEO.
Backend выполняет до двух раундов поиска
через подключённый DataForSEO: до трёх запросов за раунд и до двух страниц
на запрос. Второй план учитывает тексты, полученные в первом раунде.
У каждого запроса сохраняются вопрос, цель, тип источника и период;
GEO и язык выдачи берутся из задачи. Повторные запросы и URL исключаются.
Общий лимит — 10 логических SERP-запросов на статью: до пяти для сбора
конкурентов и до пяти для уточнения фактов (без учёта транспортных повторов).
Во втором раунде уточнений остаётся максимум два запроса, если в первом
были выполнены три. Планировщик вызывается до двух раз на одну генерацию.

Журнал запросов, URL, выдержки и ошибки сохраняются в
`generation_context.factual_research` карточки и в метаданных результата.
Он доступен в раскрывающемся блоке «Поиск фактов» при просмотре текста
и в карточке анализа конкурентов.
Повторные попытки исправить язык используют уже собранные данные; новая
генерация или редакторская доработка выполняет свежий поиск. Недоступные
страницы и пустая выдача не считаются подтверждением факта. При ошибке
исследования генерация продолжается с доступными данными и указанием
непроверенных существенных утверждений в Editor Check. Технические страницы
и задания с отключённым сбором конкурентов этот этап пропускают.
Сейчас читаются HTML и обычный текст; PDF и страницы, требующие JavaScript,
могут остаться без доступных выдержек. Дополнительного поиска после выдачи
финального текста в этой версии нет.

## Миграции и проверки

Схема БД ведется через Alembic. Применить миграции:

```bash
make migrate
```

Базовые backend-тесты:

```bash
make test
```

На production deploy hook запускает `alembic upgrade head` перед перезапуском
сервисов.

Вход выполняется через учётную запись Webdev. `anton` — администратор,
остальные пользователи видят только назначенные им проекты.
Подробности: [авторизация и права](docs/EXTERNAL_AUTH.md).
