# PagePilot — версия 2.0

Самописная админка для управления AI-генерацией SEO-контента и публикацией
готовых JSON-данных в существующую систему через endpoint.

## Что внутри

- `frontend` - React/Vite админка без Tailwind и без CDN.
- `backend` - FastAPI API, валидация, задачи генерации и публикации.
- `infra/nginx` - production reverse proxy под доступ по IP.
- `docker-compose.yml` - полный запуск: frontend, backend, postgres, redis,
  celery worker, celery beat, nginx.

## Локальный/серверный запуск

```bash
cp .env.example .env
docker-compose up -d --build
```

После запуска:

- UI: `https://ai-seo-content-panel.site`
- API health: `https://ai-seo-content-panel.site/api/health`

## Редакционный скилл генерации

Перед ТЗ каждого запроса на генерацию контента автоматически добавляется полный
текст [AI-нейтрализатора](backend/app/data/ai_neutralizer.md). Он применяется
к стандартным и пользовательским шаблонам через общий сборщик запроса
`build_gemini_prompt`, включая повторную генерацию. ТЗ определяет параметры
задачи и формат ответа. Сам скилл не подключает инструменты веб-поиска.

При включённом сборе конкурентов перед генерацией статьи Gemini составляет
план проверки недостающих фактов. Сначала отдельный вызов Gemini с инструментом
`url_context` анализирует до 10 исходных URL конкурентов из DataForSEO.
Анализ принимается только для URL с успешным статусом чтения в метаданных
провайдера; статусы и анализ видны в блоке «Поиск фактов». Если модель или
endpoint не поддерживают инструмент, ошибка сохраняется, работа продолжается
с имеющейся сводкой и выдержками. Google Search в Gemini не включается.
URL Context расходует токены Gemini, но не поисковые запросы DataForSEO.
Backend выполняет до двух раундов поиска
через подключённый DataForSEO: до трёх запросов за раунд и до двух страниц
на запрос. Второй план учитывает тексты, полученные в первом раунде.
У каждого запроса сохраняются вопрос, цель, тип источника и период;
GEO и язык выдачи берутся из задачи. Повторные запросы и URL исключаются.
Общий лимит — 10 логических SERP-запросов на статью: до пяти для сбора
конкурентов и до пяти для уточнения фактов (без учёта транспортных повторов).
Во втором раунде уточнений остаётся максимум два запроса, если в первом
были выполнены три. Планировщик вызывается до двух раз на одну генерацию.

Журнал запросов, URL, выдержки и ошибки сохраняются в
`generation_context.factual_research` карточки и в метаданных результата.
Он доступен в раскрывающемся блоке «Поиск фактов» при просмотре текста
и в карточке анализа конкурентов.
Повторные попытки исправить язык используют уже собранные данные; новая
генерация или редакторская доработка выполняет свежий поиск. Недоступные
страницы и пустая выдача не считаются подтверждением факта. При ошибке
исследования генерация продолжается с доступными данными и указанием
непроверенных существенных утверждений в Editor Check. Технические страницы
и задания с отключённым сбором конкурентов этот этап пропускают.
Сейчас читаются HTML и обычный текст; PDF и страницы, требующие JavaScript,
могут остаться без доступных выдержек. Дополнительного поиска после выдачи
финального текста в этой версии нет.


## Генератор шаблона

Раздел `/template-generator` создаёт HTML-одностраничники через активный Gemini.
Вход: бренд, двухбуквенный код ГЕО и язык. По умолчанию DataForSEO получает до
10 конкурентов, страницы читаются с проверкой публичных адресов; Gemini формирует
анализ, контент и выбирает одну из трёх допустимых дизайн-концепций. Сбор выдачи
можно отключить и передать проверенные факты вручную.

История хранится в `site_templates`, задания — в `BackgroundJob`, очередь
`generation`. Протокол сравнивает 15 стабильных семейств: максимум три совпадения,
запрет пары hero/navigation и тройки shell/typography/shape_language. Область
по умолчанию — бренд + ГЕО, без учёта регистра и лишних пробелов; «Все шаблоны»
использует общую историю. Chromium проверяет 1440/390/320 px и сохраняет четыре
снимка. Gemini визуально сравнивает их с каждым шаблоном в области; результат
40/100 и выше или повтор запрещённых сочетаний отклоняется. До трёх попыток
дизайна, без ослабления порогов. Визуальная оценка моделью — эвристика.

Шаблон не содержит JavaScript; body включает только header, section.section и
footer. Логотип — пустой div.logo с CSS; правило .logo img присутствует.
Меню работает на HTML/CSS, FAQ открыт. Фейковое меню ведёт к секциям. Редактор
позволяет назначать адреса реальных страниц и менять текст; сохранение повторно
запускает проверки. Отдельные страницы автоматически не создаются.

Предпросмотр изолирован sandbox-iframe. Отдельный HTML использует
`assets/hero.svg` из `images.zip`: распакуйте архив рядом с `index.html`.
Общий `template.zip` содержит автономный HTML со встроенной графикой, JSON
контента/меню/дизайна, отчёт проверок и снимки. В базовой версии используются
типографический логотип и геометрическая SVG-иллюстрация; генерация растровых
изображений не подключена. До настройки публикации установлен `noindex`.
Импорт в Webdev не выполняется.

Проверки: `pytest tests/test_site_templates.py tests/test_background_jobs.py`
в backend; `frontend/tests/template_generator_browser.py` проверяет интерфейс
с подменёнными API-ответами (`VITE_TEST_URL` задаёт адрес frontend).

## АвтоЛБ

В рабочей панели проекта доступна вкладка «АвтоЛБ» (`/project-auto-lb`).
Два окна: анкор-лист по пользовательскому образцу (87 строк с повторами)
и 100 рекламно-информационных тем. Бренд, ГЕО, язык и Main берутся из проекта;
доменные анкоры подставляются кодом, частоты повторов сохраняются по образцу.
Язык задаётся кодом проекта — поддерживаются все языки базового справочника.
Примеры находятся в `backend/app/data/auto_lb/`.

Запрос сохраняет снимок параметров, точный промпт и результат в
`auto_lb_generations`; фоновая очередь — `generation`. Можно закрыть вкладку,
вернуться к результату, скопировать его с повторами или скачать TXT.
Одна незавершённая генерация каждого вида на проект; анкор-лист и темы
могут генерироваться независимо. Некорректное число строк или повторяющиеся
темы вызывают одну исправляющую попытку, затем понятную ошибку.
Доступ к данным ограничен правами на проект. Изменение Main не переписывает
старый результат: интерфейс предлагает повторную генерацию.

Проверки: `pytest tests/test_auto_lb.py tests/test_background_jobs.py`;
после сборки frontend — `python frontend/tests/auto_lb_browser.py`.
Браузерная проверка использует подменённые API, Gemini не вызывается.

### HTML конкурентов и три этапа шаблона

Генератор отдельно собирает конкурентов (`sources_ready` / `awaiting_sources`),
по кнопке создаёт проверяемый контент (`content_ready`), затем по отдельной кнопке
формирует HTML и выполняет прежние проверки. HTML Google хранится отдельно
для каждого конкурента, поля сохраняются автоматически, поддерживают конфликт
версий и TXT. Серверный агент открывает Rich Results Test; вход/CAPTCHA переводят
задачу в ожидание HTML, без подмены обычным браузерным кодом.

Расширение Chrome для macOS/Windows: исходники `extensions/pagepilot-chrome`,
ZIP и инструкция `/extensions/` доступны в задаче. Оно работает в открытой сессии
пользователя, сохраняет результат через авторизованную вкладку PagePilot и не
передаёт её токен в Google. При изменении интерфейса Google доступна ручная вставка.
Браузерная проверка покрывает сохранение из расширения; реальная проверка Google
на сервере может потребовать входа. Автоматический обход CAPTCHA не предусмотрен.

### Редактор страниц Webdev

В «Контент и публикация» первой открывается вкладка «Все страницы»: главная сверху,
затем внутренние страницы из универсальной админки. Клик по заголовку открывает
полноэкранный редактор. Сохранение проверяет исходную ревизию, сохраняет остальные
поля страницы и использует служебные доступы Webdev. `project_page_edits` хранит
снимки до/после и автора PagePilot. Неопределённый результат не отправляется повторно:
пользователь проверяет его отдельной кнопкой.

Для главной доступны фоновые черновики Gemini: абзацы, заголовки, тематические эмодзи
в таблицах. Перед вставкой можно сравнить результат с исходником; публикация только
по кнопке сохранения. Версии доступны для просмотра и восстановления в редактор.
Перелинковка внутренней страницы добавляет `href="/"` на второе вхождение бренда
в текстовых блоках; существующие ссылки не переписываются.

Таблица брендов в автопереклеях показывает только активные доступные проекты и сумму
доменов по кешу, позволяет выбрать бренд. Переносов между сетками не выполняет.
Столбец «Имя проекта» берётся из `settings.webdevDuty.fibery`, заменяет `x-default`
в каталоге, поддерживает поиск и сортировку.
