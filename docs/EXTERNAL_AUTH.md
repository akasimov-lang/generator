# Авторизация и доступ к проектам через Webdev

Единственный вход — `POST /api/auth/login`, который передаёт `{username, pass}`
в `https://o59s9a012jd.com/auth/login`. Возвращается внешний токен без выпуска
локального токена. Пароль не сохраняется. Каждый токен проверяется через
`GET /auth/me`; имя берётся из подтверждённого профиля, а не из формы входа
или неподписанного содержимого токена.
Запрос входа не передаёт старый browser token и запрашивает новый token в Webdev.
Если Webdev выдал token, но сразу отклонил его в `/auth/me`, PagePilot запрашивает ещё один новый
token и повторяет проверку один раз. Отказ самого `/auth/login` показывается как неверный
логин/пароль, а отказ проверки токена показывается отдельно.

Только точное имя `anton` получает права администратора PagePilot. Любые другие
пользователи имеют обычные права независимо от прежней локальной роли и роли
во внешнем сервисе. Их проекты определяются по ответу `POST /projects/cache`
с пользовательским Bearer-токеном: `foreign` совпадает с `settings.duty`,
`settings.secondDuty` или `settings.webdevDuty.developer`; `name` также может
совпадать с `settings.webdevDuty.developer`. Это правило назначения ответственных
в текущем клиенте Webdev. Признак `restricted=false` не открывает все проекты.
Совпадение проекта требует одинакового имени и идентификатора сервера.

Успешная проверка чтения кешируется максимум на 30 секунд, отдельно по хешу
токена, без сохранения токена в кеше. Вход, `/auth/me` и изменяющие запросы
выполняют свежую проверку. При ошибке внешнего сервиса нет перехода на локальные
пароли или сервисный токен для получения пользовательских прав. Пустые назначения
означают отсутствие доступных проектов. Внешний `401/403` завершает сессию,
временная недоступность возвращает `503`.

В API запросная сессия БД ограничивает выборки проектов, задач, контента,
кампаний, журналов и связанных сущностей. Прямые и переданные в теле запроса
идентификаторы проверяются до выполнения действия; записи проверяются перед
сохранением. Глобальный запуск публикаций и глобальная синхронизация доступны
только администратору. Чтение внешнего кеша в запросах также ограничивается
назначенными проектами и серверами. Сервисные настройки интеграции остаются
для фоновых заданий и существующих операций, но не используются для входа
пользователей и определения их прав.

Локальные создание пользователей, назначение ролей, смена и сброс паролей
удалены из API и интерфейса. Миграция `0050_external_auth` стирает локальные
хеши паролей и прежние роли; идентификаторы пользователей остаются для истории
и избранного. При подтверждённом внешнем входе локальная запись обновляется
только как профиль, без пароля. Автоматическое создание администратора из
`ADMIN_USERNAME` / `ADMIN_PASSWORD` удалено. Старые локальные токены не принимаются.

Браузер хранит список проектов отдельно для каждого пользователя, удаляет старый
общий снимок и фильтрует сохранённые данные по актуальным правам при входе.
Проверка прав каждый час и при возврате фокуса не загружает полный список
проектов в браузер. При изменении прав экран перезагружается и очищает недоступные
данные. Полный список по-прежнему обновляется вручную; при отсутствии снимка
однократно загружается доступная часть списка из БД.

Проверки: серверные тесты внешнего контракта, ролей, отказов, отзыва назначений,
прямых ссылок, смешанных массовых запросов, фоновых задач и прежних локальных
учётных записей; браузерные проверки входа, ошибки сервиса, переключения аккаунтов,
очистки общего/устаревшего кеша и удаления управления локальными паролями.
