# Протокол вариативности текстов V1

## Область действия

Протокол применяется ко всем темам внутри одного задания на генерацию. Его задача — не допустить, чтобы страницы одного задания создавались по одному структурному шаблону с заменой ключевых слов и синонимов.

Формат ответа, требования безопасности и обязательные элементы темы остаются общими. Архитектура публичного текста общей быть не должна.

## Как протокол работает в системе

1. Система получает полный упорядоченный список тем задания.
2. Каждой теме назначается воспроизводимый паспорт `V01`–`V30`.
3. Паспорт задаёт шесть независимых параметров: смысловой угол, тип вступления, логику разделов, основной сканируемый формат, ритм абзацев и тип завершения.
4. Для первых 30 тем создаются 30 различных структурных чертежей. Это соответствует действующему ограничению задания в 30 тем.
5. Модель получает текущий паспорт и карту паспортов всех соседних тем задания.
6. Протокол добавляется после рабочего промпта, поэтому его требования к композиции имеют приоритет над примерами структуры из старых промптов.
7. Использованный паспорт сохраняется в `generation_meta.variability`, чтобы результат можно было проверить после генерации.

## Что считается структурным повтором

Нарушением считается любой из вариантов:

- одинаковая последовательность функций H2, даже если заголовки перефразированы;
- универсальный каркас вида «введение → краткий ответ → обзор → методология → безопасность → платежи → FAQ → вывод»;
- одинаковые первый смысловой ход, основной формат сравнения и тип финала;
- один набор разделов, переставленный местами;
- FAQ, повторяющий одинаковые вопросы для соседних тем;
- различия только на уровне слов, брендов, гео или примеров.

## Допустимые общие элементы

Одинаковыми могут оставаться только технические и обязательные требования:

- строки `Title`, `Meta Description`, `H1` и формат `H2`;
- фактически необходимые legal/safety сведения;
- предупреждение об ответственном отношении к азартным играм;
- FAQ, если он включён настройками задания;
- факты и термины, без которых нельзя корректно раскрыть тему.

Даже обязательный смысловой блок следует интегрировать в архитектуру конкретной темы, а не копировать целиком вместе с соседними разделами.

## Критерии приёмки одного задания

Задание проходит проверку вариативности, если:

- у каждой темы есть отдельный паспорт;
- структурный чертёж не повторяется среди первых 30 тем;
- H2 выведены из текущего интента, а не из общего нишевого шаблона;
- соседние тексты отличаются смысловым входом, траекторией аргументации и финальным действием;
- основной сканируемый элемент используется по-разному: таблица, последовательность, чек-лист, сценарии или матрица;
- вариативность не достигается вымышленными фактами или снижением юридической аккуратности.

## Версия рабочего промпта

Рабочий промпт, спроектированный специально под этот протокол, называется `Промпт рабочий` и хранится в файле `prompts/prompt_test_1_v6.txt`. В нём намеренно отсутствует готовый перечень H2.
