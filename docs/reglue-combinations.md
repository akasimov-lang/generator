# Комбинации переклеев и история наблюдений

При расчёте нового плана сохраняются действующие доли типов Main, поддоменов, редиректов и контентных работ. Каталог схем выбирает комбинацию внутри уже выделенного типа и canonical. Обязательный родительский x-default, выбранный резерв, ограничения совместимости и явно выбранный шаблон сохраняют приоритет. Для обычного запуска явно заданная базовая схема `locale_base` остаётся базовой; Auto Pilot распределяет варианты после расчёта квот.

Идентификатор комбинации описывает фактическую схему: тип и происхождение Main, создание и семейство имени поддомена, canonical, роли/хосты/пути альтернейтов, новую или текущую внутреннюю страницу, 301, режим заголовков, короткий H1, абзацы и внутренние страницы. Случайные имена доменов и путей не делают структурно одинаковую схему новой. Неиспользуемые настройки не увеличивают число вариантов. Совпадающие по результату варианты каталога объединяются.

Приоритет выбора: меньше завершённых запусков комбинации для «бренд + GEO», затем для проекта, затем меньше повторов в текущем плане и общей истории. Черновики учитываются только как распределение текущего плана. Ошибочные и незавершённые запуски не считаются проверенными. Старые комбинации восстанавливаются из сохранённых планов; отсутствующий исторический бренд/GEO не подменяется текущими данными проекта.

В план сохраняются `planning_options`, `combination_settings`, `combination_id` и `combination_history`. В интерфейсе показывается число прошлых успешных запусков и совместимых вариантов. Повторное выполнение использует сохранённый план и не выбирает комбинацию заново. Настройки именования массовых поддоменов берутся из эффективных настроек проекта с прежним правилом глобального переопределения.

Изменения Main и текущего внутреннего пути, обнаруженные синхронизацией, сохраняются отдельно в `network_state.cache_change_history` и показываются в истории проекта с пометкой «Кеш · обнаружено». Время означает обнаружение, а не точное время чужой правки. Первое получение проекта задаёт исходное состояние. При внедрении история однократно сверяется с последним сохранённым снимком подтверждённой операции; отличие помечается как сравнение с последней записью. Отсутствующие поля частичного ответа не считаются удалением значения. Повторные ответы не создают события; отражение собственной подтверждённой операции в пределах пяти минут не показывается второй записью. Метаданные наблюдений не изменяют ревизию сетки.
