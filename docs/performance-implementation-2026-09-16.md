# Оптимизация PagePilot, 16.09.2026

## Этапы 1–3

- Общий список сайтов больше не входит в запуск App и обновление рабочего экрана.
  «Сайты» показывает сохранённый общий снимок IndexedDB после входа.
  «Обновить проекты» читает список из нашей БД вручную. Бренды/статусы общие,
  избранное остаётся персональным. Прямой URL читает один проект /sites/lookup.
- Синхронизация Webdev осталась отдельным явным действием. Общий кеш не скачивается
  автоматически при переходах. Активная синхронизация хранится в БД и продолжается
  после закрытия страницы; локальный указатель позволяет снова увидеть прогресс.
- Глобальные архив/контент/провайдеры/пользователи загружаются на своих страницах.
  /content возвращает краткую модель; просмотр/редактирование читает полный текст.
- Обновление прогресса проекта читает его контент и кампании; журналы и карточка
  обновляются при смене состояний. Повторный опрос не накладывается на предыдущий,
  при скрытой вкладке частый опрос приостанавливается.
- Публикация вручную отправляет задание в очередь сразу, без ожидания времени
  публикационной кампании. В UI состояние «Публикуется»; окончательное подтверждение
  по кешу и индексация сохранены.
- Задание фиксируется в background_jobs до отправки в Redis. Dispatcher повторяет
  доставку только ещё не начатых заданий. Worker фиксирует начало до внешнего запроса;
  повторная доставка не повторяет удалённую операцию.
- Генерация, публикация, подтверждение/индексация, автопереклей, кеш Webdev,
  проверки меню и диспетчер имеют отдельные очереди и workers.
  Генерация ограничена двумя процессами, CPU/память workers ограничены.
  API имеет повышенный CPU-приоритет и два процесса; инициализация БД выполняется
  один раз до их запуска. Старую очередь celery продолжает обслуживать generation
  worker для совместимости уже отправленных заданий.
- Прямые короткие действия и API старой синхронизации сохранены для совместимости.
  Это изоляция процессов и ресурсов на одном сервере, не отдельный физический хост.

## Docker

infra/systemd/pagepilot-build-cache-cleanup.service и .timer:
часовой таймер удаляет только неиспользуемый кеш сборок,
не использовавшийся более 240 часов (10 дней). Политика Docker основана на
последнем использовании записи кеша. Активные контейнеры, образы запуска
и тома БД/Redis этой командой не удаляются.

Установка: скопировать оба unit-файла в /etc/systemd/system/; выполнить
systemctl daemon-reload, enable --now для таймера и start для сервиса.

Основание: https://docs.docker.com/reference/cli/docker/buildx/prune/

## Проверки

Полный backend suite; браузерные сценарии списка сайтов, всех вкладок,
автопереклея и ручной сетки. Проверены брокер недоступен, повторная доставка,
сохранение автора публикации, ручная публикация раньше расписания,
изоляция маршрутов очередей. Внешние мутации в тестах подменены.
Разбор зависших задач — отдельный финальный этап.

## Исправление первого открытия общего списка

Пустой IndexedDB после обновления больше не означает пустую систему.
При первом открытии «Сайты», «Избранное» или рабочего экрана общий список
один раз читается из нашей БД. Оба экрана используют этот общий снимок.
Повторные открытия не перечитывают весь список; «Обновить проекты»
обновляет его явно. Это чтение БД, без скачивания кеша Webdev.
Строки выбора проекта компактные: домен и персональная звёздочка,
без статусов и количества пунктов меню.

## Разбор исторических зависаний

На 16 сентября обнаружены девять строк в generation_queued/generating:
шесть у nvcasino-poland.com (25 августа) и три у pomocy.waw.pl (26 августа).
Workers не выполняли эти задания; active/reserved/scheduled были пустыми.
Эти даты предшествуют коммиту 35bb705 (26 августа, 16:47 UTC),
включившему acks_late и reject_on_worker_lost. До него остановка worker
после раннего подтверждения могла оставить состояние БД без сообщения в очереди.
Это установленный механизм потери, но не доказанная причина каждого случая:
исторических логов остановки для точной атрибуции нет.

Добавлен явный инструмент app.generation_recovery для выбранных старых ID.
Он проверяет ответы generation worker, очереди с приоритетами и unacked
до блокировки строк и повторно перед изменением. Отсутствие ответов или
любая работа блокирует восстановление. Строки моложе семи дней запрещены.
Статус переводится в generation_failed с объяснением и возможностью ручного
повтора; JSON, тексты, параметры, история и опубликованные строки сохраняются.
Повторный вызов ничего не меняет. Автоматического повторного запуска AI нет.
Инструмент не добавлен в планировщик: возраст сам по себе не доказывает зависание.

Проверки: полный backend suite — 346 тестов; отдельные случаи свежих и
опубликованных строк, сохранения содержимого, недоступного worker,
активного задания, очереди и unacked. Браузерные сценарии списка и вкладок
прошли с общей первоначальной загрузкой и без повторного полного чтения.

### Границы выполненного

Обновление UI пока использует защищённый опрос, а не SSE. Переход на события,
разделение JS по страницам и дополнительные индексы требуют отдельной
проверки; они не объявляются выполненными. История публикаций не удалялась.
