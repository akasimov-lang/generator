# Еженедельная текстовая сводка PagePilot

Раздел `/weekly-reports` содержит кнопку «Отчёт за эту неделю» и архив.
Ссылка на неделю: `/weekly-reports?week=2026-11-02` (дата понедельника).

Неделя начинается в понедельник 00:00 Europe/Moscow, заканчивается перед
следующим понедельником. Celery Beat каждую минуту вызывает
`app.worker.refresh_weekly_digests` в очереди maintenance. Новый отчёт
создаётся на первом тике недели, текущая сводка пересчитывается каждые
15 минут. Открытая страница перечитывает её раз в минуту. Открывать браузер
для накопления работ не требуется. После простоя пропущенные недели
создаются последовательно; PostgreSQL advisory lock исключает двойной запуск.

Хранилище — `AutoReglueConfig` с ключами `weekly-digest:YYYY-MM-DD`.
В начале новой недели предыдущая получает последний снимок и закрывается.
Закрытые сводки не изменяются последующими тиками; оригинал текста из чата
за 2–8 ноября сохранён отдельно в `saved_text`, обновление статистики его
не перезаписывает. Версия формата — 1. Нужна авторизация; ограниченным
пользователям статистика и текст пересчитываются только по доступным сайтам,
исходный общий текст из чата им не раскрывается.

Формат: общие результаты, Fontan, Lemon, Pelican, BetOnRed, польские и чешские
общие ключи; подтверждённые смены Main, типы доменов, 301, Title/H1, тексты,
внутряки, опубликованные страницы, переносы, витрины, шаблоны и меню.
Количество операций отличается от числа проектов. Фоновые ошибки генерации
и публикации одной логической работы не суммируются дважды. В конце одна
строка: «Незавершённые задачи и задачи с ошибками: N — требуют ручного разбора».

Сборщик только читает подтверждения БД, журналы публикации, квитанции работ
через чат и сохранённое состояние сеток. Никакие переклеи, генерации или
публикации не запускаются. Дата снимка сети не подменяется временем сборки
отчёта. Неподтверждённые схемы обозначаются отдельно, работы по ним сохраняются.
При включённых альтернейтах Canonical главной берётся из
`canonicalFakeMainMarkup`, согласно контракту Webdev. Исторический текст
из чата сохраняется дословно, актуальная сводка использует исправленный расчёт.

Ручная инициализация после выкладки: `weekly_digests.tick(db, force=True)`
в штатном backend-контейнере. API `/api/weekly-digests` и
`/api/weekly-digests/{monday}` только читают готовые результаты.
