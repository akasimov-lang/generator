# Повторный подбор освобождённых резервов

Планировщик версии 6 исправляет пропуск проектов после распределения доли поддоменов. Ранее первоначальный выбор занимал резерв в плане, а последующая замена этого выбора на поддомен освобождала резерв без повторного рассмотрения пропущенных проектов.

При подготовке нового предпросмотра:

1. Сохранить снимок сетки только для пропуска из-за исчерпания кандидатов. Ошибки чтения, отключённое участие и прочие причины не делают проект кандидатом на повторный подбор.
2. После распределения поддоменов определить конкретные записи базы резервов, освободившиеся в этом же плане. Домены, которые остались Main или родителями в других планах, исключить.
3. Повторно проверить исходную группу, права доступа, участие, недельное ограничение и отсутствие активного переклея. Проверить доступность резерва, бренд, GEO, BAN, историю Main и принадлежность сеткам. Изменённая или занятая запись резерва не подходит.
4. Добавить восстановленный проект в тот же план и пакет запуска. Сохранить в `reserve_reallocation` прежнюю причину пропуска, источник освобождения и выбранный резерв. Удалить восстановленную строку из списка пропусков пакета.
5. Пересчитать доли для итогового состава. При освобождении следующего резерва повторить подбор; число итераций ограничено исходной выборкой. Подготовить тексты после завершения распределения.
6. Резервирование и публикация выполняются только при явном запуске просмотренного плана. Предпросмотр не резервирует домены и не отправляет изменения Webdev.

Область исправления: освобождённые записи базы резервов в процентном режиме с приоритетным подбором. Группа доноров не расширяется. Для AZ сохраняется запрет автоматического выбора резервных дропов. Ранее запущенные отчёты не пересчитываются; старый черновик нужно обновить перед запуском из-за изменения версии планировщика.

Проверки: `backend/tests/test_pilot_released_reserves.py`; связанные наборы выбирает `scripts/check_changes.py`.
