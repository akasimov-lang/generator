# Webdev-задачи при редиректе фейковой внутренней страницы

После каждого подтверждённого переклея и смены фейковой страницы PagePilot проверяет **точный** URL
с текущим Main, сохраняя регистр и завершающий слеш. Проверка работает для ручных
и массовых операций, включая завершение отдельного обновления head. Сканер
запускается каждые 15 секунд; старая история до включения не обрабатывается.
При подтверждении переклея проверка сохраняется в той же транзакции, даже если
путь внутряка не изменился. Используется новый Main и сохранённый путь страницы;
при необходимости читаются старые снимки `journal_before`/`journal_after`.

Если выбранный URL отвечает HTTP 301, создаётся задача типа
`Alfasearch Config/Webdev Tasks` со статусом **New**, привязанная к SEO-проекту
из Fibery-поля PagePilot. Поле Page URL содержит полный проблемный URL.
В описании: полный адрес проекта, выбранная страница, фактическое направление
редиректа, требование HTTP 200 на выбранном адресе и проверка отсутствия петли.
Обнаруженная петля перечисляется в описании со всеми проверенными переходами.
Если различается только завершающий слеш, указывается точный обратный 301
с варианта URL на выбранный URL. Перенаправлять главную на внутряк нельзя
предлагать автоматически, если фактический редирект ведёт на главную.

PagePilot сохраняет ответ GET и ограниченную цепочку редиректов. Не переходит
на сторонние домены. Сетевые ошибки и 4xx/5xx повторяются с задержкой, максимум
шесть попыток; они не выдаются за подтверждённый редирект. Смена актуального
Main/пути отменяет устаревшую проверку.

Открытая задача для того же проекта и URL используется повторно. Если она закрыта,
а проблема появилась снова, создаётся новая. UUID сохраняется до запроса Fibery,
после неопределённого ответа выполняется чтение того же UUID. Чужие изменения
названия, URL, описания и привязки не перезаписываются. Ссылка отображается в
примечаниях проекта и в общей подборке задач Fibery.

Текущая автоматизация ставит задачи Webdev; сама настройки редиректов не меняет.
