# Алгоритм исследования и управления витринами

Проверено 02.11.2026 на польских и чешских проектах PagePilot. Источник истины — живая версия Webdev; кеш может не содержать шаблоны. `app/showcase_management.py` определяет подключения, извлекает данные для просмотра и выдаёт внутренние инструкции. Системные пометки сохраняются в `ProjectPageEdit` с отдельным ключом `showcase:management`, статусом confirmed и детерминированным UUID. Они не публикуются на сайт. Повторная проверка неизменного источника не создаёт дубликат; неполный кеш не заменяет подтверждённые сведения.

| Хранение | Подключение | Управление |
|---|---|---|
| `data.casinos.<group>` | Используемый шаблон с `each casinos.<group>` | Таблица PagePilot: редактирование текста/логотипа, POST `/projects/casinos` |
| Шорткод `.hbs` | Блок shortcode, вложенный partial, layout | Просмотр в PagePilot; менять конкретный шорткод в Webdev |
| `home.content.blocks[].data.code` | Блок code в редакторе страницы | Просмотр в PagePilot; менять блок в редакторе главной страницы |
| `home.content.blocks[].data.html` | Блок raw | Просмотр в PagePilot; менять HTML-блок в редакторе страницы |
| `home.content.blocks[].data.content` | Таблица Editor.js с колонками бренда и бонуса | Просмотр в PagePilot; менять таблицу в редакторе страницы |
| `layout` | HTML прямо в шаблоне или partial | Менять шаблон в Webdev; проверить область действия на внутренних страницах |
| `home.banners` | renderBanner/pageBanners и именованные шаблоны | Менять подключённый баннер в Webdev |
| Внешний iframe/script | Виджет поставщика | Пометка «внешняя витрина»; локальная запись запрещена без установленного контракта |

Для каждой новой или перерабатываемой витрины обязателен [протокол уникального дизайна](showcase-design-protocol.md): отдельная концепция для проекта, открытые условия и проверка опубликованного вида. Стандартизация данных не означает общий внешний вид.

## Порядок работы

1. Найти текущий проект, GEO, Main и сервер. GEO нормализовать (`PL`, `pl_PL`, `pl-PL`; `CZ`, `cs_CZ`, `cs-CZ`). Домен `.pl` или слово Czech само по себе не доказывает GEO.
2. Сохранить исходную главную, layout, используемые шорткоды и casinos. Обойти реальные подключения с защитой от циклов. Не включать неиспользованные шаблоны, basic-галерею, header/footer и случайные упоминания бренда.
3. Определить источник каждой карточки. HTML может содержать текстовый заголовок бренда без изображения; `star`, `Hodnocení`, `Licence` не бренды. Учитывать code/raw/table, а не только shortcode.
4. Для сравнения бонусов сохранять точный источник, валюту, процент, денежный предел, FS и ограничения. Сравнивать предложения одного бренда. Не брать максимальные части из разных офферов; не подставлять сумму джекпота/вывода в поле бонуса. Разные валюты или несопоставимые типы отмечать отдельно. Не переносить депозит, вейджер или рейтинг из другого оффера без основания.
5. При добавлении сохранять существующие карточки побайтово по JSON. Пользовательская правка существующего бонуса имеет приоритет над источниками. Новые бренды добавлять без дублей; названия-алиасы объединять осознанно.
6. Перед мутацией создать долговечную квитанцию, проверить revision и сохранить полную копию изменяемого узла. Один POST без автоматического повтора. После таймаута — чтение результата; не пересылать запись вслепую.
7. Логотипы: сначала искать бренд и его алиасы в общей библиотеке через `app.showcase_logo_library.entries()` / `find(brand)`. Файлы хранятся в `backend/app/data/template_assets/showcase`, источники, SHA-256, размеры и рекомендуемый фон — в общем `manifest.json`. Для витрин использовать только `showcase_ready: true`: старый favicon из каталога шаблонов не заменяет проверенный логотип. `prepare_upload(brand)` возвращает PNG и сведения об источнике без сетевых запросов; запись в Webdev по-прежнему требует квитанции. Если бренда нет, получить официальный логотип, проверить на светлом и тёмном фоне, добавить PNG и метаданные в библиотеку через Git. Не создавать дубликат при совпадении бренда/алиаса; новый вариант хранить с отдельным идентификатором и назначением. Проверять читаемость на фоне витрины. `/projects/image` принимает PNG/JPEG; PagePilot также преобразует WebP в PNG. Реальный сервер отклоняет SVG. После загрузки добавить запись в basic.logo и связать карточку по ID, сохранив старую галерею. Не хотлинковать новые изображения.
8. Подтвердить сохранение чтением Webdev, проверить публичные карточки, картинки и кеш. Хранить источники, before/after, квитанцию и результаты проверки вне исходников. Код и конфигурацию выкладывать только Git.

Текущие границы: универсальное inline-редактирование HTML/шорткодов не реализовано. PagePilot показывает их тексты и точный способ управления; никаких автоматических миграций в native-формат. Новые внешние форматы сначала исследовать, добавить контрактные фикстуры и только затем включать запись.

## Подготовка файлов логотипов

Постоянное требование от 10.11.2026: при подготовке, загрузке и пополнении библиотеки приводить к сопоставимому размеру сам видимый знак, а не только внешний контейнер. Убирать лишние поля исходного файла; квадратная иконка с маленькой надписью внутри не заменяет широкую версию логотипа. По возможности получать исходный wordmark достаточного разрешения. Не растягивать пропорции, не перерисовывать официальный знак и не обрезать его значимые части. Оригинал сохранять отдельно, нормализованный вариант — отдельным файлом с источником, размерами, SHA-256 и описанием обработки. Проверять читаемость и занимаемую площадь рядом с другими брендами на светлом и тёмном фоне, в десктопной и мобильной карточке. Одного `object-fit: contain` недостаточно, если в самом файле большие пустые поля.

## Кеш показателей витрины

Колонка «Витрина» получает количество уникальных подключённых брендов вместе со списком проектов из системного кеша `showcase-cache:<site_id>`. Открытие таблицы, поиск и фильтры не запускают запросы витрин в Webdev. В записи сохраняются бренды, источники, время проверки и время изменения состава.

Полная синхронизация, обновление одного проекта и события Webdev обновляют показатель. Если в агрегированном кеше нет шаблонов, ставится одна фоновая задача чтения проекта; повторные события объединяются, пока она ожидает или выполняется. До подтверждения сохраняется предыдущее значение. Подтверждённое удаление витрины даёт 0; неполные данные и внешние виджеты не считаются нулём. Сохранение карточки в редакторе также обновляет кеш после подтверждения Webdev.

## Стандартизация по явному поручению

`app/showcase_standardization.py` подготавливает перенос подключённых HTML-карточек и рейтинговых таблиц в native-группы `pagepilot_standard_*` и общие шаблоны `casinos-standard-*`. Это отдельная операция с собственным отчётом, полным исходным проектом, планом, проверкой версии и квитанцией каждого POST. Бонусы, условия, логотипы и ссылки переносятся из исходника; данные неиспользуемых групп сохраняются. Текст вне карточек остаётся на месте. Если карточки, бонусы или полный состав брендов не определены, публикация не выполняется. После записи обязательны чтение Webdev и проверка публичных страниц; неподтверждённые запросы автоматически не повторяются.

Создание файла шорткода и сохранение содержимого — два шага. Официальный клиент использует `POST /projects/shortcode/new` с `project`, именем без `.hbs`, `requiredPermission: create-shortcode`, `initiator`; затем `POST /projects/shortcode`. Каждый шаг подтверждать отдельным чтением. Ответ 201 на редактирование отсутствующего файла не доказывает создание. Кнопки переносятся вместе с исходными `data-split`, обработчиками и атрибутами; разные офферы одного бренда на разных страницах не объединяются.
