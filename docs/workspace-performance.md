# Быстродействие вкладок проекта — 16.09.2026

## Найденные задержки и изменения

- GET сетки обращался к Webdev при новом открытии страницы. При наличии полного
  сохранённого снимка теперь возвращаются данные нашей БД и история операций.
  `?refresh=true` явно запрашивает Webdev; при отсутствии снимка сохраняется
  первоначальная загрузка. Проверки перед изменением проекта остаются свежими.
- Обзор запрашивался также для генерации, меню и публикаций. Теперь он загружается
  только для вкладки обзора.
- Результаты независимых запросов отображались после завершения всей группы.
  Теперь каждый ответ обновляет свой блок сразу. Запоздалый ответ другого проекта
  или уже закрытой вкладки не подменяет текущие данные.
- Кеш уничтожался при смене проекта. Теперь он общий для открытого рабочего экрана,
  изолирован по пользователю и URL проекта, ограничен 200 записями и TTL 30 секунд.
  Изменения очищают кеш, повторные одновременные GET объединяются. Принудительное
  обновление обновляет и обычный снимок сетки.
- Настройки автопереклея повторно читались при возвращении на вкладку. Их снимок
  теперь кешируется; опрос активных задач обходит кеш.
- Начальное открытие системы ждало архив, общие списки и административные данные.
  После авторизации запросы выполняются параллельно, рабочий экран появляется
  после получения проектов и провайдеров, остальные данные приходят фоном.
- ORM загружал тела статей и полные журнальные payload даже для кратких списков.
  Списки контента, последние материалы обзора и краткие логи выбирают из БД только
  поля соответствующих ответов. Полные данные остаются доступны там, где нужны.

## Проверка

- Browser-тест всех семи вкладок: повторный обход в пределах TTL — 0 новых запросов.
- Искусственно задержанный архив не блокирует появление сетки.
- Искусственно задержанные разделы не блокируют отображение обзора.
- Открытие сетки с сохранёнными данными не вызывает Webdev; явное обновление вызывает.
- Проверены ручные действия, автопереклей, сохранение настроек, обновление и ошибки
  кеша. SQL-тест подтверждает отсутствие generated_json в запросах кратких списков.

Это проверки поведения на локальном стенде; проценты ускорения на проде не измерялись.
